## 1. 项目概述

### 1.1 项目背景

AI Recorder 是一个面向 Windows 个人用户的录音整理工具，核心链路为：音频导入 → ffmpeg 格式归一化 → FunASR 离线转写 → 云端 LLM 摘要 → 前端展示与导出。现有系统采用模块化单体架构（FastAPI + SQLite + React/Vite），在用户 PC 上本地运行。

本产品旨在为 AI Recorder 提供 Android 移动端远程访问能力。采用 **PC 后端留守 + Cloudflare Tunnel 内网穿透 + Android 远程客户端** 的技术方案，使用户在离开家庭局域网后仍能通过手机录音、上传、查看转写和摘要。

### 1.2 产品定义

AI Recorder Android 客户端是一个**远程管理客户端**，支持从手机直接上传音频文件到 PC 端。它负责远程浏览录音库、查看转写和摘要结果、导出内容和系统监控。**App 内不提供实时录音功能**——但用户可通过系统文件选择器从手机选取已有音频文件，上传至 PC 后端的目标目录，由后端完成后续的转写与摘要处理。所有音频处理（转写、摘要）均在 PC 后端完成。敏感数据（音频文件、转写结果、摘要内容）始终留在用户自己的 PC 上，遵循"核心数据本地化"原则。

### 1.3 技术方案概述

```
┌──────────────────────┐                              ┌──────────────────────────┐
│   Android 客户端      │         HTTPS（公网）         │   Windows PC              │
│ （管理 + 上传 / 无录音）│ ◄──────────────────────────► │                           │
│ ┌───────────────────┐ │                              │ ┌───────────────────────┐ │
│ │ 录音库浏览         │ │  REST API + X-API-Token     │ │ FastAPI 后端          │ │
│ │ 转写/摘要查看      │ │ ◄──────────────────────────►│ │ 端口 8000             │ │
│ │ 导出/删除          │ │                              │ └───────────────────────┘ │
│ │ 文件上传（📤）      │ │                              │           ▲               │
│ │ 系统健康监控       │ │                              │           ▲               │
│ │ 设置管理           │ │                              │           │ TCP           │
│ └───────────────────┘ │                              │ ┌─────────┴────────────┐ │
│                       │                              │ │ cloudflared 隧道     │ │
│                       │                              │ │ (Windows 服务)        │ │
│                       │                              │ └──────────────────────┘ │
│                       │                              │           │               │
└──────────────────────┘                              └───────────┼───────────────┘
                                                                  │
                                                          ┌───────┴───────┐
                                                          │  Cloudflare   │
                                                          │  CDN + HTTPS  │
                                                          │  Edge         │
                                                          └───────────────┘
```

**核心设计决策**：

- Android 端为**远程管理客户端**——App 内不提供实时录音功能，但支持从手机文件系统选取音频文件上传至 PC 端
- 音频处理全部在 PC 端完成，Android 端通过隧道远程浏览管理及文件上传
- 通信协议为 **HTTPS**，认证方式为共享 **API Token**
- **PWA 作为快速验证方案**——改造现有 React 前端指向隧道域名，Android Chrome 打开即可用
- **原生客户端作为长期目标**——Kotlin Compose 方案，提供原生移动体验

## 2. 产品目标与成功指标

### 2.1 产品目标

| 目标 | 说明 | 成功标准 |
|------|------|---------|
| 远程转写可达 | 随时随地查看 PC 上的转写和摘要结果 | 4G 网络下打开 App 到看到转写结果 < 5 秒 |
| 数据本地化 | 音频和转写始终在用户 PC | Android 端不持久化任何音频或转写内容 |
| 开箱即用 | 首次配置不超过 3 分钟 | 用户 10 分钟内完成隧道搭建 + App 登录 |
| PWA 快速体验 | 扫码即用 | 4G 下冷启动 < 3 秒 |

### 2.2 成功指标

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 服务器可达率 | ≥ 99% | 客户端 `/health` 探测成功率 |
| 列表加载速度（WiFi） | 100 条录音 < 2 秒 | 客户端请求耗时打点 |
| PWA 冷启动时间（4G） | < 3 秒 | Lighthouse / Web Vitals |
| 24 小时空闲后唤醒延迟 | < 5 秒 | 用户测试 |
| 详情页打开耗时 | < 1 秒 | 转写/摘要接口耗时打点 |
| 认证错误率 | < 1 次/100 次会话 | 后端 403 错误日志 |
| 隧道每周宕机时间 | < 10 分钟 | 可用性监控 |

## 3. 目标用户与使用场景

### 3.1 用户画像

**主要用户**：使用 AI Recorder 做会议记录、访谈整理、课堂笔记、日常语音备忘的个人知识工作者。

| 属性 | 描述 |
|------|------|
| 职业背景 | 知识工作者、研究人员、记者、学生 |
| 技术水平 | 中等——能跟随配置指南操作，非开发者 |
| 设备 | 中高端 Android 手机（Android 10+） |
| 网络环境 | 家庭 WiFi + 4G/5G 移动网络 |
| 使用频率 | 每天 1-3 次查看 |
| 典型操作 | 查看转写结果、浏览摘要、导出内容 |
| 隐私关注度 | 高——不希望音频数据留在云端 |

### 3.2 核心使用场景

| 场景编号 | 场景描述 | 频率 | 优先级 |
|----------|---------|------|--------|
| **S0** | 收到别人发来的会议录音 → 在手机上选取文件上传到 PC 端 | 每周 | P0 |
| **S1** | 通勤路上（4G）→ 查看最新的转写结果 | 每天 | P0 |
| **S2** | 会议结束后 → 在手机上查看摘要和待办事项 | 每周 | P0 |
| **S3** | 在外出差 → 查看历史录音的转写内容 | 每周 | P0 |
| **S4** | 查看讲座录音的摘要 → 导出 Markdown 分享给同事 | 每周 | P1 |
| **S5** | 检查 PC 后端健康状态 → 确认 FunASR / ffmpeg 是否正常 | 每月 | P1 |
| **S6** | 清理旧录音 → 远程删除不需要的录音及转写 | 每月 | P2 |

### 4.2 F1：录音库模块（P0）

**F1.1 录音列表**

| 项目 | 规范 |
|------|------|
| 内容 | 从 PC 后端拉取的录音列表（与 Web 端数据源一致） |
| 列表项信息 | 文件名、时长、状态徽章、相对时间 |
| 状态徽章 | ✓ 已完成（绿底#E8F8F0/#1A8C5B） / ⏳ 转写中（黄底#FFF7E6/#D48806） / ⚠ 失败（红底#FFF1F0/#F5222D） |
| 排序 | 默认最新在前，点击切换正序 |
| 下拉刷新 | 下滑刷新列表 |
| 空状态 | 居中插画 + "还没有录音。点击右下角 📤 上传音频文件，或通过 PC 端导入。" |
| 加载状态 | 骨架屏占位符 |
| 错误状态 | 网络错误提示 + 重试按钮 |

**F1.2 搜索与筛选（P1）**

| 项目 | 规范 |
|------|------|
| 搜索 | 输入框按文件名过滤（低于 100 条客户端筛选，以上加服务端分页） |
| 筛选标签 | 状态（未处理/已转写/已完成/错误）、来源（上传/监控）、时长范围 |
| 当前筛选指示 | 搜索栏下方显示彩色标签，点击 × 移除 |

**F1.3 录音详情（P0）**

| 项目 | 规范 |
|------|------|
| 导航方式 | 点击列表项 → 推入详情页 |
| 分区 | 顶部 Tab 切换：转写 / 摘要 / 信息 |
| 转写 Tab | 含时间戳的分段文本；可一键复制全部 |
| 摘要 Tab | 渲染的 Markdown，支持一键复制 |
| 信息 Tab | 文件名、时长、文件大小、格式、来源、创建时间 |
| 任务进度 | 如果有任务运行中，显示进度条及状态文字 |

**F1.4 导出（P1）**

| 项目 | 规范 |
|------|------|
| 入口 | 转写/摘要 Tab 内容区域底部的操作栏 |
| 格式选项 | Markdown (.md) 或 纯文本 (.txt) |
| 按钮布局 | 左侧边框按钮"复制文本"（#1A8C5B 边框 + 白底）、右侧填充按钮"导出 MD"（#1A8C5B→#2BAF7A 渐变） |
| 反馈 | Toast 提示"已复制到剪贴板" / "正在导出..." |
| 文件名 | `{文件名}_转写_{时间戳}.md`（与 Web 端命名一致） |

**F1.5 删除（P0）**

| 项目 | 规范 |
|------|------|
| 触发方式 | 详情页顶栏右侧删除图标 |
| 确认方式 | Toast "删除成功"（原型阶段简化，后续版本可加弹窗确认） |
| 后端行为 | 调用 `DELETE /api/recordings/{id}`，级联删除转写、摘要、任务 |
| 删除后 | 从列表移除；如当前正在查看该录音，回退到列表页 |

### 4.4 F3：系统健康面板（P1）

### 4.5 F4：文件上传模块（P0）

**F4.1 上传入口与交互**

| 项目 | 规范 |
|------|------|
| 入口 | 录音库首页右下角 FAB（Floating Action Button），图标 📤 |
| 点击行为 | 唤起 Android 系统文件选择器（Storage Access Framework），限定音频 MIME 类型 |
| 支持的格式 | `.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.flac`, `.wma`, `.opus`, `.amr`（与后端支持的 ffmpeg 可处理格式对齐） |
| 多选 | 支持一次选取多个文件（上限 10 个） |
| 上传方式 | `multipart/form-data`，字段名 `file`，调用 `POST /api/recordings` |
| 目标目录 | 后端自动保存至 PC 端配置的存储目录（`RECORDINGS_DIR`） |

**F4.2 上传状态管理**

| 项目 | 规范 |
|------|------|
| 上传列表 | 点击 FAB 后弹出底部 Sheet，展示当前正在上传和等待上传的文件列表 |
| 单文件上传项 | 文件名 + 文件大小 + 进度条（百分比）+ 状态文字（等待中/上传中/已完成/失败） |
| 并发 | 串行上传（一次一个），其余显示"等待中" |
| 失败重试 | 单个文件上传失败后显示重试按钮；用户可手动重试 |
| 取消上传 | 正在上传的文件可取消（发送取消信号，不等待后端响应） |
| 全部完成 | 所有文件上传完成后，底部 Sheet 显示"全部上传完成"，用户关闭后刷新录音库列表 |
| 后台行为 | 用户离开上传 Sheet 后，上传继续执行；通知栏显示上传进度（P1） |

**F4.3 上传结果反馈**

| 项目 | 规范 |
|------|------|
| 成功 | 文件项显示 ✅ 绿色标记 |
| 失败 | 文件项显示 ⚠️ 红色标记 + 错误原因文字（网络超时 / 文件格式不支持 / 服务器存储空间不足） |
| 部分成功 | "3/5 个文件上传成功"，失败项提供重试按钮 |
| Toast | 上传全部完成后弹出 "N 个文件已上传，PC 端将自动开始处理" |

**F4.4 上传限制与验证**

| 项目 | 规范 |
|------|------|
| 单文件大小上限 | 500 MB（后端限制，前端可选做客户端预检提示） |
| 格式校验 | 选择文件时通过 MIME type 过滤；上传前二次校验扩展名 |
| 网络状态检查 | 上传前检查服务器可达性（`GET /health`），不可达时提示"PC 离线，无法上传" |
| 移动数据提醒 | 当检测到非 WiFi 连接且单个文件 > 50 MB 时，弹窗提示用户确认 |

|------|------|
| 网络容错 | API 请求失败指数退避重试（1s, 2s, 4s）；3 次失败后提示用户检查网络 |
| 隧道断开检测 | 每 60 秒探测 `/health`，断开时显示常驻"PC 离线"横幅 |
| Token 过期处理 | 收到 403 时跳转设置页，提示用户检查 Token |

### 5.3 安全性

| 需求 | 规范 |
|------|------|
| API 认证 | 所有请求（`/health` 除外）必须携带 `X-API-Token` 头（32+ 位随机字符串） |
| Token 存储 | `EncryptedSharedPreferences`（Android 原生）加密存储 |
| Token 传输 | 仅通过 HTTPS 传输；POST 请求不在 URL 参数中传递 Token |
| 日志脱敏 | API Token、文件路径、转写内容禁止出现在 logcat 或控制台日志 |
| 代码混淆 | Release 构建启用 `minifyEnabled = true` |

### 6.3 API 契约

Android 客户端使用以下后端 API（读写操作通过 Token 认证）：

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| `GET` | `/health` | 无 | 健康检查（连通性测试 + 启动时探测） |
| `GET` | `/api/recordings` | Token | 列出所有录音 |
| `GET` | `/api/recordings/{id}` | Token | 录音详情 + 转写段落 + 摘要 + 任务 |
| `DELETE` | `/api/recordings/{id}` | Token | 删除录音（级联删除） |
| `GET` | `/api/recordings/{id}/exports/transcript?format=md\|txt` | Token | 导出转写 |
| `POST` | `/api/transcribe/{id}` | Token | 启动转写任务（远程触发） |
| `POST` | `/api/summary/{id}?mode=...` | Token | 启动摘要任务（远程触发） |
| `GET` | `/api/summary/templates` | Token | 获取摘要模板列表 |
| `GET` | `/api/summaries/{id}/export?format=md\|txt` | Token | 导出摘要 |
| `DELETE` | `/api/summaries/{id}` | Token | 删除摘要 |
| `GET` | `/api/settings/llm` | Token | 读取 LLM 配置（只读） |
| `GET` | `/api/settings/storage` | Token | 读取存储设置（只读） |
| `GET` | `/api/settings/watch` | Token | 读取监控设置（只读） |
| `GET` | `/api/watch/events` | Token | 查看监控事件 |

**认证方式**：除 `/health` 外，所有请求必须携带：
```
Header: X-API-Token: <32位以上随机字符串>
```

**上传格式**：`POST /api/recordings`，`multipart/form-data`，字段名 `file`，支持多文件（客户端串行发送多个请求）。后端返回包含新创建的录音记录 JSON。

### 6.4 本地数据模型

Android 客户端为远程管理客户端，不持久化录音文件本体或转写内容，仅持久化以下配置：

```
┌───────────────────────────────────────────────┐
│              DataStore 配置存储                 │
│                                                │
│  ┌─────────────────────┐                      │
│  │ 服务器配置            │                      │
│  │─────────────────────│                      │
│  │ serverUrl: String    │  隧道域名             │
│  │ apiToken: String     │  加密存储（Encrypted │
│  │                      │  SharedPreferences） │
│  │ themeMode: Enum      │  浅色 / 深色 / 跟随   │
│  │                      │  系统（默认）         │
│  └─────────────────────┘                      │
└───────────────────────────────────────────────┘

   录音列表、转写内容、摘要内容等均来自 PC 后端 API，
   客户端不做本地持久化缓存（后续版本可选增加）。
```

## 8. 数据安全设计

### 8.1 数据流转与保护

```
┌─────────────────────────────────────────────────────────┐
│                     数据流转示意                          │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  Android 端                       公网                  │
│  （音频透传 / 无本地持久化）                               │
│  ┌─────────────┐                                       │
│  │ 📤 音频文件  │──── HTTPS ──────────────────┐         │
│  │ （内存）    │                             │         │
│  └─────────────┘                             │         │
│  ┌─────────────┐                             │         │
│  │ API Token   │──── HTTPS ──────────────────┤         │
│  │ （加密存储） │                             │         │
│  └─────────────┘                             │         │
│                                               ┌────────▼───┐
│  ┌─────────────┐                              │ Cloudflare  │
│  │ 转写/摘要   │──── HTTPS ──────────────────►│ Edge        │
│  │ 浏览缓存    │                              │ （TLS 终结） │
│  │ （内存）    │                              └─────┬───────┘
│  └─────────────┘                                    │
│                                                      │
│  ⚠ Android 端不持久化任何       ┌──────────▼───────┐ │
│     录音文件或转写内容           │  PC 后端          │ │
│     所有数据均在 PC 端存储       │  （唯一数据源）    │ │
│                                  └──────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 8.2 安全措施清单

| 层级 | 措施 | 实现方式 |
|------|------|---------|
| 传输层 | HTTPS（TLS 1.3） | Cloudflare 自动提供 SSL 证书 |
| 传输层 | 证书绑定（P1） | OkHttp CertificatePinner 锁定隧道域名 |
| 认证层 | X-API-Token 所有请求 | AuthInterceptor 自动注入；`/health` 豁免 |
| 存储层 | 加密 SharedPreferences | `MasterKeys.AES256_GCM_SPEC` 加密 Token |
| 存储层 | App 私有文件存储 | 上传的音频仅在内存中暂存，不写入磁盘；如需缓存选择临时目录 `context.cacheDir` |
| 代码层 | 日志脱敏 | Release 构建中 Token 和文件内容不写入 logcat |
| 代码层 | 代码混淆 | Release 构建启用 `minifyEnabled = true` |
| 网络层 | Token 不在 URL 参数 | POST 请求 Token 仅通过 HTTP Header 发送，避免 URL 日志泄露 |

### 8.3 隐私说明

> **AI Recorder 不会将您的音频文件或转写内容存储在任何云服务器上。** 所有数据处理（FunASR 转写、LLM 摘要）均在您个人的 Windows PC 上完成。Android 客户端通过加密隧道将音频从手机安全传输到您的 PC，上传过程中音频仅在内存中暂存，不写入手机本地存储。Cloudflare 提供加密隧道通道，隧道内部流量已经过 TLS 加密。如有额外隐私需求，可考虑 frp 自建隧道方案。

### 9.1 技术选型（原生路线）

| 层级 | 技术 | 选择理由 |

| Markdown | WebView + marked.js 或 Markwon | 摘要内容渲染 |
| 异步 | Kotlin Coroutines + Flow | 响应式数据流 |

### 9.2 技术选型（React Native 轻量路线）

| 层级 | 技术 | 选择理由 |
|------|------|---------|
| 框架 | React Native 0.76+ + Expo SDK 52 | 跨平台，开发更快 |
| 导航 | expo-router | 文件系统路由 |
| 状态管理 | Zustand 或 Context + useReducer | 轻量级 |

| 存储 | AsyncStorage + expo-secure-store | 配置存储 + Token 安全存储 |
| Markdown | react-native-markdown-display | 应用内 Markdown 渲染 |
| UI 样式 | NativeWind（Tailwind CSS for RN） | 熟悉的样式方案 |

### 9.3 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 数据源 | 纯远程 API，不做本地持久化 | Android 端为远程客户端，PC 是唯一数据源；上传的音频通过内存流发送，不落地 |
| 服务器连通检测 | 启动时 + 每 60 秒 `GET /health` | 快速发现隧道断开，提示用户 |
| Token 存储 | `EncryptedSharedPreferences`（原生）/ `expo-secure-store`（RN） | Android 安全最佳实践 |
| 任务进度轮询 | ViewModel 中协程 `delay(2000)` 循环；任务完成或离开页面时停止 | 简单；MVP 阶段避免 WebSocket 复杂性 |
| Markdown 渲染 | React Native：`react-native-markdown-display`；原生 Compose：WebView + marked.js | 轻量，能正确渲染摘要模板输出 |
| 列表加载策略 | 一次性全量拉取 + 客户端筛选排序（100 条以内）；超阈值走服务端分页 | 个人使用场景通常 < 100 条，减少请求次数 |

## 11. 风险评估与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 隧道服务因流量过大冻结账号 | 低 | 高——App 不可用 | 监控 Cloudflare 免费套餐限制；以 frp 自建隧道为备选 |
| PC 断电或休眠 | 中 | 高——App 不可用 | App 显示"PC 离线"横幅；提供 PC 不休眠配置指引 |
| Cloudflare Tunnel 连接中断 | 中 | 中——暂时不可用 | cloudflared 自动重连；App 显示"PC 离线"横幅；重连后自动恢复 |
| Cloudflare IP 频繁变更 | 低 | 低 | cloudflared 透明处理 |
| 后端版本不兼容 | 低 | 中 | API 版本头协商；优雅降级 |
| Token 泄露 | 低 | 高——数据暴露 | Token 仅在 EncryptedSharedPreferences 加密存储；通过 HTTPS 传输；支持随时更换 |

### 应急预案：隧道回退方案

如果 Cloudflare Tunnel 变得不稳定或被限制，可回退到 frp 自建隧道：

```
Android ──► frps（¥50/月 轻量 VPS）──► frpc（PC）
```

Android 客户端存储主备两个服务器地址，通过设置页切换。

```xml
<!-- AndroidManifest.xml — 网络 + 文件选取权限 -->
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
<!-- 以下仅用于检测 WiFi 状态，以触发移动数据上传提醒 -->
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
```

> 说明：文件选取通过 Android Storage Access Framework（SAF）实现，无需 `READ_EXTERNAL_STORAGE` 权限——系统文件选择器由 Android 系统代为授权。App 不需要录音权限（`RECORD_AUDIO`）和前台服务权限（`FOREGROUND_SERVICE`）。共需 3 个权限，均为"安装时授予"级别，无需运行时弹窗授权。
